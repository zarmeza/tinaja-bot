## Tried and failed

- The first `tinaja-bot new` run omitted `--lang ruby`, so the generator produced the Python layout
  (`cogs/`, `tests/`). Fixes: deleted that folder (nothing user-made was lost) and regenerated outside the
  framework repo, because a Bot is a separate project and must not nest inside `tinaja-bot-base`.
- `zanoria save --help` is not a flag check: `save` treats everything after it as the task line, so it
  wrote `Task: --help` into this note. Reverted with `git restore .carrot.md` (the note was committed).
- `gh repo rename` on an archived repo fails with `HTTP 403: Repository was archived so is read-only
  (https://api.github.com/repos/zarmeza/tinaja-bot)`. Fix: PATCH `{archived: false}`, rename, PATCH
  `{archived: true}` again. Old URLs keep redirecting until a new repo claims the name — creating the
  new `zarmeza/tinaja-bot` did exactly that.
- The push to an existing ghcr package from a repo that is not on its access list fails as
  `denied: permission_denied: write_package` (registry HTTP 403, surfaced by buildx). The first owner
  grant didn't take (wrong repo or Read-only was selected); after re-adding `zarmeza/tinaja-bot` with
  Read and write and rerunning, the same run's attempt 3 pushed fine.
- The keyless-web hunt (2026-11-06), all from the owner's machine: DuckDuckGo lite/html answers HTTP 202
  with a "bots use DuckDuckGo too — select all squares containing a duck" CAPTCHA; Mojeek 403s; the
  public SearXNG pool is dead for programs (searx.be serves "Verifying your browser…", others 000/429/403);
  Tavily 403s unauthenticated; Brave is geo-blocked from Venezuela. Do not retry any of these as the lamp;
  the feeds (Google News/Bing RSS) and the trade APIs are what actually answers.
- Bing's RSS relevance for castellano topical asks is weak (it shredded "quién ganó la liga FUTVE" into
  FARMAPATRIA pharmacy pages); Google News RSS nailed it (Carabobo, Apertura 2026). Hence the ladder order
  Google News first, Bing for the wider web — do not "fix" the order back.
- `pkill -f "tinaja-bot run"` also matches the invoking compound shell and kills it before the rest of the
  chain runs; use the bracket trick `pkill -f "[t]inaja-bot run"` or kill the uv parent by pid.
- Discord quirk (2026-11-06): `GET /users/@me/channels` returned an empty list for the bot even though the
  owner's DM channel had existed since 2023. `POST /users/@me/channels` with `{"recipient_id": "<user id>"}`
  returned that same channel id. If a DM looks invisible, POST is the reliable lookup; don't trust the GET
  listing for bots.
