- Greenfield bot: it is a re-interpretation, not a port. Nothing was read or kept from any earlier bot project.
- Ruby Commands via the framework's multi-language path: a Python host (from `tinaja_base`) owns the Discord
  connection, and `plugin/bot.rb` is the Plugin (`tinaja` gem) it talks the protocol to over stdin/stdout
  (see `bot.toml` `[plugins.main]`).
- The framework is a git dependency, not a local path: `pyproject.toml` pins
  `https://github.com/xionjames/tinaja-bot-base` to rev `main` (2c773a1), and `plugin/Gemfile` gets the
  `tinaja` gem from the same repo (same ref, `glob: sdk/ruby/*.gemspec`). Rejected `--source <local path>`
  (editable, but `tinaja-bot check`/build refuses path sources for images).
- `plugin/Gemfile.lock` carries `x86_64-linux` and `aarch64-linux` so the Docker image builds reproducibly.
- `DISCORD_BOT_TOKEN` lives only in the untracked `.env` (copied from `env.sample`); Plugins never see it.
